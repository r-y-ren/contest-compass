## 二、深构条目（前五名全深构；材料等级 A：官方 Devpost 提交页全文直抓 + 官方展示页）

### POLYFORK（1st place，$500,000，Lucas Martinic · 德国 · Small Business Services）

材料：Devpost 提交页全文快照（kb/raw/devpost-build-with-gemini-xprize/winners/2026-10-01-devpost-1126044-polyfork.md）+ 官方展示页 + XPRIZE 公告。

**解题/创作骨架**（技术方案主线，5 步）：

1. **起点换元**：把"3D 模型=成品文件"重新定义为"3D 模型=程序（parametric code module）"——用户先改参（recolor/resize/remix）后下载；agent 的原生材料是代码，故资产天然 AI-native。
2. **内容生产 agent 化**：人类只写一行需求 → agent 展开为 production brief，Gemini 画参考图（Vertex AI on Google Cloud，AI Studio 兜底 + 每日 liveness check 邮件）；第二个 agent 把模型写成代码；harvest 循环=渲染实测。
3. **质量闭环**：测量 harness 报告"实际渲染出的 GLB"而非 agent 自述；另一 fresh-session judge agent 按 brief+kit 规则评分——1000+ attempts 被评分、约 2/3 被打回；人工再打回 633 次（跨 349 资产）。
4. **商业形态**：kit 化资产（统一 4m 网格/调色板/构建规则）；ES module 经 URL 直接 import（`createAsset({tallness:0.9, facets:16})`）；免费层 295 个模型公开 + Pro=运行时依赖（订阅=可 import 的持续服务，边缘缓存 30 天）；agent 消费面 /llms.txt + REST API + MCP server。
5. **业务自身同构 AI 化**：周一 SEO audit agent（8-11 提案 4 项、批 3 项、17 分钟上线）；自造"agent 客户"持真实任务+仅公开 API 提可回放 bug report；每次构建沉淀 lessons 文件蒸馏注入后续构建（40% lessons 来自无人查看的构建）。

**亮点**（按官方评审三维度归类）：

- **[Business Viability] 真收入、真分发**：上线首日（2026-08-01）即有首单，月内 54 个付费客户、$4,428 收入、43/100 创始终身席售出、每周有收入；零关联方收入（self-reported，提交页 2026-08-17 时点）。
- **[Business Viability] 定价即架构**："订阅=运行时依赖"把 SaaS 经常性收入语义注入 3D 资产售卖（npm 安装包类比），并以创始终身席做早期现金流——两种变现并行。
- **[AI-Native Operations] 全产线 agent 工厂**：175 模型/周的发布速率由无人值守 agent 产线支撑（人类监督不画图）；judge-in-fresh-session + 测量 harness 是"AI 生产质量工程化"的范本。
- **[AI-Native Operations] 可验证的自我改进**：lessons 文件→蒸馏→注入未来构建的闭环，且以"10.3GB 转录/604 builds/1743 graded passes/1591 snapshots"全标注语料作为下一层资产（attempt/critique/correction 配对数据）。
- **[Category Impact] 生态位卡位**：为 prompt-to-world 平台（Tencent WorldClaw 2026-08-06 的 Terrain Asset Prototypes 槽位）预置"AI-native 资产库"——查询式供给、参数化变体零生成成本、licence 可商用；295 个免费模型即公共获客门。

**不足与可改进点**（评审视角；标注为分析判断）：

- 收入绝对值小（$4,428/月）相对 $500k 大奖，评委实质押注轨迹与范式而非当期营收；条目未给出留存/复购数据支撑"运行时依赖"的续费假设。
- 单人公司（bus factor=1），扩产计划依赖招"监督 agent 产线的人"，组织可行性未验证。
- judge agent 自认"filter 不是 gate"，质量上限仍系于 633 次人工打回——"无人值守"与"人类把关"的张力未解决。
- 跨 kit 组合（joinable across kits by arithmetic）仅有承诺，未见跨 kit 一致性验证证据。
- 对 Google Cloud/Gemini 成本结构未披露（175/周的产线成本影响毛利）；被 I 核对的维度：营收真实性（self-reported 未经独立核验，但赛事提交要求 Stripe 导出+P&L 为评审材料，可信度较高）、复购、成本、组织、生态承诺兑现。

**可迁移性**：

- **fresh-session judge agent + 测量 harness**（"测量再相信"）：任何 AI 生成产线（文书/代码/模型）可平移，改造成本低——把"自述质量"换成"对成品实测+独立会话评审"即可，本框架 verify 环节可直接借用。
- **lessons 蒸馏注入循环**：构建/写作复盘→共享文件→注入未来提示词；40% lessons 来自无人查看的构建说明该循环可自发产生——低成本，高复用。
- **"要程序不要图"**：让 AI 产出带参数的生成器而非一次性成品，使交付物天然可迭代可 diff——适用于我们的一切作品形态（PPT/代码/论文）。
- **agent 客户 dogfooding**：造一个仅持公开接口的 agent 用户持续提可回放 bug report，作为免费 QA——适用于 API/产品类战役。
- **创始终身席 + 订阅双轨**：早期现金流与经常性收入并行的冷启动定价，可复用于作品商业化设计。
- 复用成本估计：前四条≈1-2 人日/条（模式清晰）；第五条需业务设计≈3-5 人日。

### TICIAN CIERRE（2nd place，$200,000，José Edgar Peña Ramírez · 墨西哥 · Small Business Services）

材料：Devpost 提交页全文快照（2026-10-01-devpost-1124454-tician-cierre.md）+ 官方展示页 + XPRIZE 公告。

**解题/创作骨架**（4 步）：

1. **痛点定位**：墨西哥中小企业垫付的 VAT 退税"钱在账上但流程关不上环"——CFDI 发票与银行流水对账难 + SAT 申报要求 8 类文件格式严格一致。
2. **对账引擎**：Gemini 负责"配对/归类/写人读的说明"（发票↔银行流水，含部分付款/核销/取消）；**Python 做全部算术**（求和、余额、税率、舍入）——模型提议、代码验证。
3. **申报包生成**：月度关账产出 SAT 要求的全套结构化文件（metadata bundle + 客户目录 + 每 CFDI/每付款 XML，8 类 artifact 相互一致）。
4. **独立审计**：第二个 Gemini 实例（Vertex AI，on Cloud Run 的 FastAPI/Docker/VPS 架构，最小权限 service account）以"怀疑型资深会计师"角色审计整套关账——不通过则附理由打回重建；每份关账附带审计报告。

**亮点**：

- **[Business Viability] 直接的钱**：帮企业拿回已垫付的 VAT（可量化回收额）；已在真实会计师工作负载上跑通——227,000 张真实 CFDI、零重复零幽灵付款；全系统跑在 $12 VPS 上（成本纪律）。
- **[AI-Native Operations] builder/validator 分离**：审计者与构建者不同会话、无共享记忆、无利益关联（借文学理论 Bakhtin"外位性/exotopy"命名）——把"新会话防偏袒"上升为方法论。
- **[AI-Native Operations] 模型提议/代码算术的边界纪律**：LLM 一碰算术就"subtly wrong"，收窄到分类与解释后变可靠——生产级 LLM 应用的职责切分范本。
- **[Category Impact / Small Business Services] 打拉美中小企业的税务后厨**：Self-serve e.firma 接入路线图 + "AI 准备的财税工作审计报告格式开放标准"构想。
- **诚实工程叙事**：三次"以为做完了"均由"分歧"发现缺陷（测试数据由同源代码生成掩盖缺陷、UUID 重复致重复计数 2026-08-03 修复、贷项单符号错误致退税×2 2026-08-12 修复）——评审恰恰奖励这种可核验的诚实。

**不足与可改进点**（分析判断）：

- 提交页未披露收入/付费客户（accomplishments 引 workload 而非 revenue）——赛事要求收入证据，其形态可能是"有客户但金额不亮眼"或"以工作量证明替代"，落选第一名或与此相关（对比 Polyfork 的收入前置叙事）。
- 单一税制（墨西哥 SAT）深绑定，市场天花板明显；LatAm 扩张仅是路线图。
- "auditor 不是 gate"意味着最终仍需人工复核——对 SMB 用户而言"谁来看审计报告"的运营成本未展开。
- e.firma（税务私钥）接入是高信任门槛，安全叙事仅到"最小权限 service account"，密钥处理细节未披露。
- 核对维度：收入披露、市场宽度、信任与安全、自动化完成度。

**可迁移性**：

- **"模型提议、代码验证"**：任何涉数字/日期/金额的 AI 应用切分法，成本极低（≈0.5-1 人日改造）。
- **fresh-context 审计者模式 + 报告随产物交付**：我们的 KB 条目/作品自检可平移——评审输出作为交付物一部分（而非内部 gate），既留存证据又提升可信度。
- **"分歧找 bug"测试法**：三个真 bug 全靠 builder 与 validator 或人工账目的分歧暴露——提示我们 verify 阶段应构造独立第二路径而非重复同一逻辑。
- **Bakhtin 外位性命名**：把工程约束讲成方法论叙事的表达技巧，零成本可借用。

### MYFIXAM（3rd place，$100,000，Jane Chukwuyem Odum with Ayodele · 尼日利亚/美国 · Small Business Services）

材料：Devpost 提交页全文快照（2026-10-01-devpost-1041321-myfixam.md）+ 官方展示页 + XPRIZE 公告。

**解题/创作骨架**（4 步）：

1. **痛点定位**：尼日利亚数百万手艺人（学徒制出身、无 CV、无评价体系）被口碑网络锁死收入；93% 非正规就业无安全收款方式；现有平台抽成过高。
2. **AI 承担全部"数字门槛"**：五个生产级 Gemini 2.5 Flash 系统——画像生成器（10 分钟对话→职业档案）、需求接入与路由（自然语言/语音/照片→29 个工种类目）、内容审核（拦截导流与违规）、支持助手、通知 agent（按订单史/天气/本地活动个性化每日摘要）。
3. **信任与支付**：escrow 预付（Paystack，尼日利亚可靠代管通道）+ 完工 24h 内放款、10% 抽佣；人工核验每一位 artisan（ID+技能面谈+推荐电访）——"AI 管规模、人管信任"。
4. **本地化工程与增长**：PWA（3G 下 3 秒加载、离线看缓存档案）；超局部流动性打法（Gwarinpa 一街区供给+需求双密集启动再复制）；对账层日核对 Paystack webhook 与实际到账。

**亮点**：

- **[Business Viability] 冷启动真实数据**：2026-07-02 上线、首月 370+ 用户（零广告）、平均完成订单 ₦90,000（≈$64，接近许多非正规工人月薪）；期内注册 MYFIXAM LTD（CAC）+ 开对公账户；escrow 零纠纷。
- **[Business Viability] 增长第二曲线清晰**：侨汇支付（ diaspora 客户为家乡雇人但 Stripe 不覆盖尼日利亚）+ artisan 信用档案（6 个月 escrow 史→信贷画像，Shopify Capital/Stripe Capital 打法平移到无征信人群）。
- **[AI-Native Operations] 约束优于提示词**：路由器只能输出 29 类目之一（不能发明第 30 类）；定价建议=附近同类完成订单中位数（不能幻觉金额）；审核服务端严格 pass/block 无"maybe"——五个 AI 系统全部以"收窄模型自由度"保可靠性。
- **[AI-Native Operations] 本地语言工程**：审核层理解尼日利亚英语/Pidgin（"I go charge you small for materials"曾被误判为欺诈→加提示层）。
- **[Category Impact] 非正规经济的金融化路径**：从"更多订单+安全收款"到"订单史=征信"，直指 EHP/MFA 交叉的结构性问题。

**不足与可改进点**（分析事实+分析判断）：

- 最大收入机会（国际支付）在提交时点未解决：Stripe 不服务尼日利亚，Paystack 只做本币——提交页自认"we're working on it"。

- 留存/复购数据未披露（370+ 用户为注册口径，非活跃/复购口径）。
- 核对维度：支付通道、留存、规模化成本、信任面。

**可迁移性**：

- **约束优于能力**的 prompt 设计（封闭枚举+统计基线+禁"maybe"）：零成本，适用于一切对幻觉零容忍的场景（我们的数据纪律可直接套用该表述）。
- **超局部流动性打法**（单街区供需双密集→口碑→复制）：适用于任何双边市场类作品/战役的冷启动章节。
- **"信任建于打款而非承诺"**：冷启动叙事论据的组织方式（首笔放款后转介绍爆发）——写作层可平移。
- **PWA 低端机工程底线**（3s/3G、<单张 Instagram 照片的体积）：技术选型论证素材。

### LAUNCHBRIDGE（4th place，$100,000，Chase Rosen with Bryan and Leo · 美国 · Entrepreneurship & Job Creation）

材料：Devpost 提交页全文快照（2026-10-01-devpost-1118450-launchbridge.md）+ 官方展示页 + XPRIZE 公告。

**解题/创作骨架**（4 步）：

1. **痛点定位**：2/3 美国人有创业想法仅 12% 迈出第一步；阻碍是官僚流程（州注册/IRS/注册代理/合规）——先访谈弗州小企业主（清洁合作社/家教/绿化队/餐车）再写代码。
2. **产品形态**：6 个自然语言问题 → Gemini 2.5 Flash 分类业务描述/抽取实体信息/预填所有表格 → 人工确认（review 而非填表）→ AI agents 办完全流程：VA SCC 州注册、EIN 申请、建站、Stripe 配置；之后合规日历盯年报截止。
3. **无 API 攻坚**：弗州 SCC 门户（2003 年代）与 IRS EIN 均无公开 API——用 Playwright（辅以 Claude）逐屏人工踩点 40+ 屏，抓字段/校验/报错规则后由 agent 自动导航。
4. **AI-native 的可度量定义**：Evidence Layer 记录每单流程中 AI 份额 vs 人工份额（逐项打时间戳可审计）；安全面：SSN/EIN 入 KMS 加密保险库+自动轮换。

**亮点**：

- **[Business Viability] 定价重构信任**：$350 一口价（含 $100 州费）vs 律师 $500-3,000 且隐藏收费——6-12 周→72 小时；注册代理 $110/年 vs 竞品 $129-349/年；期内有真实付费客户完成真实注册（非 demo）。
- **[Business Viability] 第三方公信力**：WTOP News（DC 地区头部新闻台，2026-07）与 Arlington Magazine 报道、American Edge Project 撰文、弗州 SBDC 网络表达转介意向——获奖前已完成本地生态背书。
- **[AI-Native Operations] Evidence Layer**：把"AI-native"从口号变成可测指标（AI 份额可审计）——与本赛 AI-Native Operations 维度严丝合缝的自证设计。
- **[AI-Native Operations] 无 API 政府系统的 agent 自动化**：40+ 屏映射是脏活壁垒（"会调 API 的很多，肯踩点 2003 门户的几乎没有"——moat 论证）。
- **[Category Impact / EJC] 递延收入路线**：合规监控（年报/特许税/注册代理续费）作为 launch 后经常性收入；SBDC 转介渠道（月触达数百新创始人）。

**不足与可改进点**（分析判断）：

- 仅弗吉尼亚一州（深度换广度）， TAM 自限；扩州=逐州重踩门户，扩张成本线性。
- 门户改版即断链：agent 自动化对政府前端无契约保障，脆弱性未给出监控/修复 SLA。
- 模糊分类边界案例（"在集市摆摊偶尔网上卖"）需要追问式对话层——提交页自认未预先设计。
- 高敏感数据面（SSN）：KMS 叙事有，但合规认证（SOC2 等）未提及——对目标客群的信任成本仍在。
- 上线量/单量等运营数字未披露（"real paying customers"无计数）。
- 核对维度：市场宽度、自动化鲁棒性、数据合规、运营数据。

**可迁移性**：

- **"无 API 就逐屏踩点"**：面对封闭系统的 agent 自动化方法论（含成本结构：一次踩点换长期壁垒）——适用于政务/遗留系统类战役，≈3-5 人日习得。
- **Evidence Layer**：任何"AI 服务"作品可内建"AI 份额审计层"作为评审自证——≈1-2 人日，且与本赛评审语言同构。
- **顺序依赖设计**（EIN 先于 Stripe 配置、中间不破坏 72h 承诺）：流程型作品的依赖管理叙事。
- **先访谈后代码**：需求发现章节的标准写法（本作品以四类小企业主访谈开场）。

### DODOPREP —— The Autonomous Learning OS（5th place，$100,000，Naveed Ahmed · 印度[公告]/美国[展示站] · Education & Human Potential）

材料：Devpost 提交页全文快照（2026-10-01-devpost-1127092-dodoprep-the-autonomous-learning-os.md）+ 官方展示页 + XPRIZE 公告。

**解题/创作骨架**（4 步）：

1. **痛点定位**：学生不缺材料（PDF/录课/幻灯片满地）缺"陪着啃自己那套材料的人"——家教 $40-100/时，YouTube 不知道你会什么。
2. **多模态摄入**：Gemini 原生吞 PDF/扫描件/音视频/YouTube/PPT/docx——免建 OCR/转写/版面解析三条独立管线；管线含版面检测、语义分块、抽取质量校验（坏抽取标记重试而非静默产出坏课程）。
3. **课程与辅导生成**：严格 JSON schema 约束的课程结构（章节/目标/概念图）；RAG 接地（tutor 引用学生自己文档，超纲答"你的材料没讲"）；自适应测验（按概念级掌握度加练+间隔重复）。
4. **工程与增长**：FastAPI + Gemini + Vertex 嵌入 + Cloud SQL 向量检索 + Cloud Run/GCS；异步任务队列+状态通知+激进缓存控成本；产品已上线 dodoprep.com；路线图=跨会话记忆/严格考官模式/班级视图（聚合全班弱项）/离线移动端/多语言。

**亮点**：

- **[Business Viability] 已上线真实产品**（dodoprep.com 可注册即用）；成本/延迟工程明确（异步队列+缓存，避免重传即重跑全管线）；班级视图路线图指向 B2B 第二曲线。
- **[AI-Native Operations] 拒答式接地**：tutor 被约束为"材料没讲就说没讲"——幻觉治理以产品行为而非提示词技巧落地（提交页自述 tutoring 准确性因此显著提升）。
- **[AI-Native Operations] 抽取质量门**：生成课程前先校验多模态抽取质量，坏抽取换策略重跑——"垃圾进垃圾出"的工程化拦截。
- **[Category Impact / EHP] 指导权民主化**：把 $100/时家教体验变成"对你自己的材料"的无限耐心辅导；低连接地区与多语言列入路线图。

**不足与可改进点**（分析判断）：

- 提交页零用户/收入数据——与前四名"真收入"叙事对比，纯产品可用性叙事在本赛属弱势（收入证据是该赛硬门槛，其提交必然附了收入证据但页面未展示数额）。
- AI tutor 赛道拥挤，提交页未做与现有工具的差异化论证（未提及任何竞品对照）。

- 核对维度：traction、竞争定位、量化评估、单位经济。

**可迁移性**：

- **RAG+拒答**（引用自己语料+超纲声明）：KB 问答/作品答辩材料可直接套用，≈1 人日。
- **生成前抽取质量门 + schema 约束的结构化产出**：一切"文档→结构化交付物"管线的通用两道闸，≈0.5-1 人日。
