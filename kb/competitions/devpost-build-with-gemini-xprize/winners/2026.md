## 二、深构条目（8 项：全部 5 席 Finalist + 2 席类别奖 + 1 席 Runner Up 形态代表）

### Polyfork（1st place，$500,000，Lucas Martinic · Germany，单人）

**解题/创作骨架**（依据：项目页全文 × 官方公告）：
1. **切入点**：3D 资产消费端与生产端同时 agent 化——模型不再以静态文件交付，而是"参数化小程序"（recolor/resize/remix 即改参数重编译），像 npm 包一样经 URL 安装（项目页 Inspiration：agents 写软件的时代，资产也该是可编程物）。
2. **生产侧 = agent 工厂**：Gemini 起草制作 brief + 参考图（Vertex AI 文本生成，AI Studio 兜底，每日 liveness check）→ 第二个 agent 把模型写成代码 → 自渲染 harness 实测产物 GLB → 独立评审 agent（全新会话、对 kit 规则打分）把关——**评审 agent 打回 1000+ 次尝试中的约 2/3，人工再打回 633 次（跨 349 个资产）**。
3. **交付侧 = 面向人与 agent 双消费**：`/llms.txt`、公开 REST API、MCP server；赛中来自 29 个 key 的 14,524 次 API/MCP 调用。
4. **运营侧 = agent 化**：周一 SEO 审计 agent 提出变更、批准后 17 分钟上线；"self-customer" agent 定期以客户身份使用产品并提交摩擦报告。
5. **知识闭环**：每次构建写 lessons，蒸馏进共享 lessons 文件并复制进未来构建——**10 条 lesson 里 4 条来自无人查看的构建**。

**亮点**（对应评审三准则 Business Viability / AI-Native Operations / Category Impact，等权）：
- Business Viability：**有真实收入轨迹**——上线首日（2026-08-01）即首单，此后每周有收入；首月 583 个模型（295 免费）获 54 名付费客户、$4,428 收入；100 个创始人终身席位卖出 43 个；主动声明关联方收入为零（公告口径 + 项目页）。
- AI-Native Operations：这是全场把"业务由 agents 运营"做到最纯粹的样本——产品由 agent 工厂量产（周产 175 个模型）、渠道面向 agent（API/MCP/llms.txt）、运营由 agent 值班（SEO 审计/self-customer），提交物层面的 agent 留痕（10.3 GB transcripts / 604 builds / 1,743 次评分通过）可直接回查。
- 工程可信度：harness 哲学 "measure, then believe"——不信任 LLM 自述，独立会话评审 agent + 实测渲染，与人审双层打回机制（项目页原文口径）。
- 诚实披露：Stripe 曾在赛中拆成两个账户，导致收入轨迹难连读——主动写进项目页（证据质量 > 叙事完美的信号）。

**不足与可改进点**（核对维度：收入量级/赛道定义/披露完整性）：
- 收入绝对值小（首月 $4,428）：总冠军的 Business Viability 并不靠营收规模，靠证据链质量与可扩展叙事——对"冲高奖"的启示是证据工程优先于冲 GMV，但对"验证商业模式强度"的读者，此值本身是上限信号。
- 类别归属未披露：Category Impact 维度上它对齐了哪个类别无法核验（官方公告未列，不猜测）。
- 页面 Built With 标签未完整截取（webReader 抓取边界），技术栈细节以正文叙事为准（Gemini/Vertex AI）。

**可迁移性**：
- "生产 agent + 独立评审 agent（新会话、规则打分、打回率留痕）"是任何生成类产品的质检骨架，可直接复用（成本：低-中，两个 prompt + 一个评分器）。
- "产品同时给人用和给 agent 用"（llms.txt/REST/MCP）是 agent 经济时代的分发前置位，成本低（文档 + 网关）。
- "lessons 文件跨构建蒸馏复用"可迁移到任何 agent 流水线的持续改进（成本：低）。
- **对冲认知**：垂直行业 Agent 不是夺顶必要条件——"AI-native 纯度 + 证据工程 + 平台想象力"可以盖过行业深度（评审终席含 Cathie Wood/Logan Kilpatrick 等，公告口径，投资人视角）。

### TICIAN Cierre（2nd place，$200,000，José Edgar Peña Ramírez · Mexico，单人）

**解题/创作骨架**（依据：项目页全文）：
1. **切入点**：墨西哥企业本可退回的 VAT（IVA）抵扣因对账/申报流程太重而被放弃——做"回收被留在桌上的钱"：读 CFDI 电子发票 XML + 银行对账单 → 对账 → 产出 SAT 规定的 8 件套申报文件。
2. **确定性内核**："Python does the arithmetic, not the model"——按 UUID 与金额和做确定性去重/求和，**Gemini 只对已解析项做判断**，算术块随响应原样带回供审计。
3. **模型当外部审计员（exotopy）**：Vertex AI（Cloud Run）上的 judgment 服务被设计为 "auditor, not a gate"——失败放行（fail-open）但记录拒绝理由；用巴赫金"外位性"概念作架构论证。
4. **真bug实捕**：validator 抓到自身代码两个真实 bug——UUID 重复导致双计（2026-08-03 修）、credit-note 符号反（2026-08-12 修）——"外部评审者"定位不是修辞而是已兑现的工程收益。
5. **部署面**：对账引擎 Docker 跑 VPS + 最小权限专用 service account；judgment 走 Cloud Run。

**亮点**：
- Business Viability：问题直接以"找回的税金"计价，价值锚点清晰；与 24 年从业的真实会计师共同设计，**227,000 张真实 CFDI 测试语料、实测零重复**（页面口径）。
- AI-Native Operations：审计留痕链路完整——算术块回带、拒绝理由落日志、fail-open 不阻断业务。
- 工程判断力："模型不做算术"把 LLM 局限转化为架构约束，是本条目所有深构对象中反复收敛出现的纪律（见画像节）。
- Category Impact：墨西哥中小企业税务合规是高摩擦刚需（公告将其排至 2nd，评委认可该垂直深度）。

**不足与可改进点**：
- 收入/客户证据未在页面呈现（页面聚焦工程与设计方法），商业化进展不可核——$200k 级项目的公开材料里这是明显留白。
- 团队规模页面未署名（公告署名单人），交付带宽与单人风险不可评估。
- "fail-open 审计员"在强合规场景的适用边界（若审计放行错误申报，责任模型）未展开。

**可迁移性**：
- "确定性内核 + LLM 判断层 + 判断理由落日志"是财税/法务/招投标等强审计场景的通用骨架（成本：中，需领域对账规则）。
- "让模型当外部审计员抓真 bug"的开发流程可直接照搬到我方 agent 作品的自测层（成本：低）。
- 价值锚点选"替客户找回钱"而非"提效"——付费意愿论证省力，可复用为选题原则。

### MyFixam（3rd place，$100,000，Jane Chukwuyem Odum · Nigeria and USA，单人 founder）

**解题/创作骨架**（依据：项目页全文；类别页自述 Small Business Services）：
1. **切入点**：尼日利亚非正式工匠经济——93% 从业者没有安全收款方式；做本地版 TaskRabbit：需求-工匠撮合 + 托管支付。
2. **Gemini 五系统**：Gemini 2.5 Flash 服务端用于 (a) 工匠档案从对话中起草、(b) 需求 intake/triage、(c) 内容审核、(d) RAG 客服助手、(e) 每日通知 agent——同一模型贯穿供给/需求/风控/客服四条线。
3. **约束优先于提示词**：价格不由模型生成——服务端取同类工时中位数定基价，模型只在约束内填充。
4. **信任落线下**：人工面对面核验工匠身份与技能——线上 agent 效率 + 线下人际信任的混合编排。
5. **真实运营**：2026-07-02 上线；370+ 用户、29 个工种；MYFIXAM LTD 注册 + 对公账户；10% 抽成模式。

**亮点**：
- Business Viability：**本条目深构对象中唯一"上线即有真实双边运营 + 营收模式已跑通"的项目**（用户数/工种数/抽成率三指标齐全，页面口径）。
- Category Impact：直接攻非正式经济金融排斥（93% 无安全收款），叙事与赛题"Small Business Services"强对齐。
- AI-Native Operations：五处 Gemini 调用全部服务端化（成本/滥用可控），而非客户端散点集成。

**不足与可改进点**：
- GMV/抽成收入绝对值未披露（370+ 用户是注册口径还是成交口径不明）。
- 线下核验的人力成本随规模线性增长，扩张模型未展开。
- 托管支付的资金合规路径（尼日利亚监管口径）未在页面说明。

**可迁移性**：
- "模型在约束内填充、平台定约束（中位定价）"是双边市场防模型幻觉报价的通用手法（成本：低）。
- "一个模型服务端串五条业务线"是低预算团队的 agent 密度样板（成本：低-中）。
- "线上 agent + 线下人工核验"混合信任编排可迁移到任何低信任市场（劳务/二手/本地服务）。

### LaunchBridge（4th place，$100,000，Chase Rosen · USA，两名大学生 + 导师）

**解题/创作骨架**（依据：项目页全文）：
1. **切入点**：把"想法→真实经营的 LLC"压缩为 72 小时流水线（弗吉尼亚州）：州务卿 SCC 注册、IRS EIN、网站、收款四件事一次办完。
2. **编排**：Python/FastAPI 跑 Cloud Run，Firestore 状态机；Vertex AI + Gemini 2.5 Flash 做分类/文案；**Playwright 浏览器自动化填政府表格时用 Claude 做表单推理**（Gemini 与竞品并用的清醒分工——规则允许）；机密入 GCP KMS vault。
3. **收款**：Stripe Connect 托管收费；定价 $350 一口价（含 $100 州 filing fee），注册代理 $110/年。
4. **Evidence Layer**：专门一层度量"AI-native 运营"证据（对齐评审准则，把评分面做成产品模块）。
5. **信任外证**：客户已付费 + 3 条 lead；WTOP News、Arlington Magazine 报道；American Edge Project 刊文；弗州 SBDC（小企业发展中心）接洽。

**亮点**：
- Business Viability：**有付费客户 + 第三方媒体背书 + 政府关系侧验证**——证据类型最多样（页面口径）。
- AI-Native Operations：Evidence Layer 是全场唯一"把评审准则工程化为可测层"的做法——评委要什么，就把它做成系统组件。
- 多模型编排判断力：浏览器自动化用 Claude、分类用 Gemini，按任务选模型而非站队。
- 面向 agent 无关的落地壁垒：州表格细节/费用结构/注册代理服务等脏活构成真实护城河。

**不足与可改进点**：
- 单州（Virginia）起点，多州复制的合规矩阵成本未披露。
- 客户数仅"付费客户 + 3 leads"口径，无量级；$350 定价的单位经济未展开。
