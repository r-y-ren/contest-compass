## 二、深构条目（每篇一节，四节必备）

### Shepherd（Treehacks Grand Prize 1st；兼 OpenEvidence Healthcare Track Grand Prize + Best Use of Clinical Information）

队伍：Tony Wang（CS@Stanford，xAI/Scale AI/Amazon Lab126/SAIL 履历）、Arjun Oberoi、Shane Mion、Anthony Chukhlov（来源：https://devpost.com/software/raising-cane ；抓取：2026-11-10；四人全名与二手校媒 Stanford Daily 2026-08-28 快照互证一致，升为一手可信）。GitHub：github.com/tonywangs/shepherd。

**解题/创作骨架**（一手项目页自述，3-5 步）：
1. 痛点定价：170 万美国人法定盲、传统盲杖不指路、现有智能杖昂贵 → 主打 "~1/20 of existing devices" 的成本替代。
2. 感知：iPhone LiDAR 60fps 深度管线，8 像素网格采样、按左/中/右三区划分可行域。
3. 决策：gap-seeking 转向算法（16 深度列找通道）+ 逆深度加权 + EMA 时间平滑（alpha=0.08）抑制死角来回摆动。
4. 执行：12 字节 BLE 包 @10Hz 发 ESP32-S3，泄漏积分器（tau=0.55s）驱动 PWM 电机**横向推动杖身**引导方向；端到端延迟 <50ms。
5. 扩展层：轮椅可达 GPS 路径（OpenRouteService wheelchair profile + Overpass 人行横道 + 6m 微路点）、Vision framework 行人检测、HSV 草地地形判别（>15% 草覆盖即 1.5m 处注入虚拟障碍）。

**亮点**（对评审三轴 Creativity / Technical Complexity / Social Impact）：
- Technical Complexity：亚 50ms 实时闭环横跨 LiDAR 感知/CV/嵌入式/BLE 通信四域，双端 watchdog（iOS 500ms / ESP32 250ms 包超时）体现实时系统工程成熟度（证据：项目页 Challenges/Accomplishments 节）。
- Social Impact：视障出行辅助 + 显性成本对比叙事（1/20），OSE 校方回顾文单独点名该项目（证据：项目页 Inspiration；https://ose.stanford.edu/news/treehacks-12-sam-altman-and-llamas ，抓取 2026-08-28）。
- Creativity/交互创新：用**电机本体触觉**而非语音播报做引导通道——"杖替你想"的交互减负；HSV 草地判别自陈 "It's dumb and it works"（ML-free 的务实取舍）。
- 与赛制文化咬合："audacious but feasible"（OSE 直抓）——成本论 + 36h 内可跑通的完整闭环正是 feasible 侧的样板。

**不足与可改进点**（必填；核对维度：项目页全文 + 两篇二手报道）：
- **无精度指标**：全页只有延迟（<50ms）无准确率——障碍检出率/误报率、室外强光下深度质量均未给，评审无法核验感知可靠性。
- 地形模块脆弱：HSV 绿色色相（60°-160°）判草地的边界场景（落叶/阴影/室内地毯）未处理，团队自陈 mulch/brown grass 是 next step——即当前实现自己承认未完成。
- 安全论述实现层化：500ms watchdog 是兜底而非 fail-safe 设计论证；面向视障用户的失效模式分析（定位丢失/电机误动）缺失，距辅具级可靠性论证有明确距离。
- 硬件形态未收敛：自陈 next step "smaller hardware"，续航/重量/佩戴负担未披露（电池置杖内、电机置底部的原型形态）。
- GPS 路径层在 GPS 拒止场景（室内过渡/隧道）无降级方案自述。

**可迁移性**：
- "感知-决策-触觉执行闭环装进传统辅具"是 Social Impact 轴高获奖概率模板；复用成本：低-中（消费级 LiDAR + ESP32 + 开源模型，但需实体迭代）。
- 工程 recipe 可直接搬：深度列扫描 gap-seeking、EMA 平滑、BLE write-with-response 减延迟、双端 watchdog——36h 可复刻的实时管线清单。
- "成本对比（1/N of existing）"一句话定价是高杠杆叙事件。
- 硬件类参赛须配现场演示预案与录屏兜底（赛制线下路演）。

### Robosurge（Treehacks Grand Prize 2nd）

队伍：Edward Li / Justin Peng / Jason Zhao / Ananth Venkatesh（队名 "Shenanigans Maxxing"；项目页未标院校，来源：https://devpost.com/software/we-use-nix ；抓取：2026-11-10）。GitHub：github.com/quantum9Innovation/treehacks2026。

**解题/创作骨架**：
1. 痛点量化开场：美国外科专科缺口 2036 年预计近 2 万、手术室成本 ~$2,200/小时/外科医生；现有手术机器人只提精度不自动化。
2. 主张："Cursor for surgery"——一人远程手术平台：外科医生经 Meta Quest 3 头部追踪同步 + 自然语言指挥机械臂，人员 10→1、距离"从几米到全球任意处"。
3. 坐标与感知：Intel RealSense + ArUco 标签仿射变换，建 12-DOF 相机-机器人坐标映射；自研逆运动学绕开 SDK 限制并给安全约束。
4. AI 层：SAM 分割 + YOLOv11 边缘部署（ASUS Ascent GX10）+ "LLM fusion between GPT-5.2 and Gemini Robotics-ER 1.5"。
5. 安全与复现：Lean 定理证明四类轨迹（lemniscate/正弦/弹簧/螺旋）处于物理安全界，自写 Runge-Kutta 解 Lorenz/Rössler 混沌系统；Nix 贯穿 dev/prod；前端 TanStack + FastAPI，WebRTC 视频/WebSocket 诊断。

**亮点**（对评审三轴）：
- Technical Complexity：IK 自研 + 12-DOF 标定 + 双 LLM fusion + VR 遥在 + 实时视频流，36h 内软硬件全栈（项目页自陈队伍为首次接触硬件的 "first-time hardware engineers"）。
- Creativity：手术版 "Cursor" 一句话定位；**在黑客松引入 Lean 形式化验证**（自陈 "likely among the first large-scale Lean uses at a hackathon"）——与全场同质化方案的强差异点。
- 工程可信度：Nix 复现 + GitHub 开源 + slug "we-use-nix" 的自指命名——评审可自行验证，降低"demo 魔术"疑虑。
- Social Impact：动机段用缺口/成本双量化数据锚定（$2,200/h、20,000 缺口），影响论有数字支撑。

**不足与可改进点**（核对维度：项目页全文）：
- **零医学验证**：无离体/仿真手术成功率或操作精度数据；自陈下一步才是 "high-fidelity medical simulations"——距真实手术场景的距离未量化。
- 鲁棒性存疑：ArUco 视觉标签定位对遮挡/光照敏感，标定误差数据未给；"no prior robotics background" 自述反衬 IK/坐标链未经工程打磨验证。
- LLM 决策风险未闭环：GPT-5.2 × Gemini Robotics-ER 的 fusion 正确率/延迟无指标，医疗场景幻觉缓解仅 "robust grounding harnesses" 一句带过。
- 远程手术关键项缺失：网络抖动/断连时的安全策略未述；力反馈/碰撞检测未实现（自陈 haptics 是 next step）——Lean 证明只覆盖轨迹几何界，不覆盖接触安全。
- 成员院校未标注，背景不可核。

**可迁移性**：
- "形式化验证当评委钩子"：Lean/证明类工件在黑客松稀缺性极高，差异化成本中（需数理背景成员），机器人/系统类赛道普适。
- "垂直领域 × Cursor 类比"命名法：一句话降低评审理解成本，任意垂直 AI 方向可套。
- 多模型 LLM fusion + 边缘盒部署的 agent 栈 36h 可搭；Nix/开源复现包是低成本可信度放大器。
- VR 头控 + 机械臂遥在是通用模板，医疗之外（远程巡检/实验操作）同样成立。

### ChromaChord（Treehacks Grand Prize 3rd；兼 Suno Best Musical Hack）

队伍：Roger You / Joe Liang / Lucy Wu（bio：Johns Hopkins CS）/ J4Joshua Tan（其余三人院校未标注，来源：https://devpost.com/software/chromachord ；抓取：2026-11-10）。GitHub：github.com/J4Joshua/JASS-APP。

**解题/创作骨架**：
1. 理论底座：物理取向音乐理论——24D chroma 向量表示和弦，目标覆盖一个八度 ~4000 和弦并按不谐和度排序；**明确回避低可解释性 LLM 做核心和弦构建**。
2. 实时输入：吉他/键盘 MIDI 直入 → chroma 向量化（以直入绕开乐器声信号处理噪声）。
3. 谐和图模型：和弦转换 + 泛音关系编码为图；确定性工具做和弦检测/调性推断/进行建议，引用 tonal interval spaces、和声变化检测、张力模型、Autochord、CQT 等文献。
4. AI 决策层：快/慢架构分离——本地实时谐和分析 与 慢速 AI 推理解耦；Perplexity Sonar API 检索同和弦进行的流行歌曲，Claude（Agent SDK）生成匹配进行的和声与旋律。

**亮点**（对评审三轴）：
- Technical Complexity：信号处理 + 图论 + 音乐信息检索（MIR）跨域整合（项目页 Accomplishments 自陈）；快慢分离是实时系统的正经架构。
- Creativity：反同质化路线——确定性物理/数学模型做核心、LLM 只作决策增强层；"~4000 chords in an octave" + 24D 向量的学术化叙事辨识度高。
- 价值轴契合（Suno Best Musical Hack 兼得）："feels like collaboration, not automation"——AI 增强而非替代人类表达，定位与技术选择自洽。
- 可信度：MIR 学术文献引用背书，区别于纯产品 demo 叙事。

**不足与可改进点**（核对维度：项目页全文）：
- 输入面窄：仅支持 MIDI 直入，麦克风音频输入的 chord detection 未实现——普通吉他手需另购 MIDI 拾音器，自陈是"绕过"而非解决乐器声信号处理。
- 和弦歧义（同一音集多解）自陈为核心挑战，但消解策略未展开。
- 无用户验证：建议延迟数字、采纳率、音乐专业性评价均缺；"real-time" 无量化支撑。
- 手工构造的谐和图：learned-embedding 图自陈为 next step；Perplexity 检索层的版权边界与离线可用性未讨论。
- 成员院校仅 1 人可核（JHU），队伍画像不全。

**可迁移性**：
- **"确定性核心 + AI 决策层"架构**是评审疲劳于纯 LLM wrapper 时的差异化模板，复用成本：低-中；艺术/文科赛道同样适用（领域理论当底座、AI 当增强）。
- 快/慢系统分离是所有实时 AI 产品的通用工程模式。
- "MIDI 直入绕过 DSP"的降维取舍思路：36h 内主动砍掉不可解问题、把资源压到核心闭环——黑客松时间管理的可复制决策。
- 领域理论 + 学术引用背书提升评审可信度，成本仅文献检索。
