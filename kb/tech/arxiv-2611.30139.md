# AutoSECO：让 agent 把"怎么开发求解器"本身进化成资产

> 来源：https://arxiv.org/abs/2611.30139 （2026-11-23，摘要经 arXiv API 实抓 2026-11-25）。无官方实现（GitHub search 2026-11-25 实查）。本卡内容出自本次抓取的摘要，未读 PDF 全文。

## 是什么

**AutoSECO**（Zirui Zhu 等），通用 LLM agent 的**自动技能进化**方法，目标是跨组合优化问题（CO）复用求解器开发经验。痛点：agent 能开发完整求解器，但专业化依赖逐题人工设计的工作流，开发专长无法复用。AutoSECO 的核心难题是**信用分配错位**——外部评估度量的是"完成的求解器"，而技能文档指导的是"开发过程中的决策"。解法：把性能缺口沿求解器代码与**记录的开发决策**回溯，定位指导缺陷；改写以**通用指令**表达；且**只有当新技能指导下新开发的求解器均值评估 gap 更低时才保留**（证伪式入库）。摘要口径：仅在 TSP 上进化，TSP 最终均值 benchmark gap **0.52%**（对照技能进化基线 SkillOpt 0.98%）；同一冻结技能跨四个 CO 问题（TSP+3）聚合成绩优于无技能指导、初始技能与 SkillOpt；并支持在**替代模型-harness 配置**下复用同一技能开发求解器。

## 解决什么问题

竞赛/工业里用 LLM agent 做 CO 求解器，经验每题一次性的浪费巨大：TSP 上调通的构造启发式思路，到 VRP/调度就丢。AutoSECO 把"开发经验"从一次性 prompt 工程变成**可进化、可验证、可迁移的文档资产**。

## 相比前方法优势

- **信用分配机制**：现有技能进化工作（含库内 FGSE 2611.14326 的证伪闸门）多在"任务结果→经验条目"层面过滤，AutoSECO 深入到"性能缺口→代码行→开发决策"的**回溯式归因**，改写的是开发指导而非补丁式经验；
- **只训一题、跨题迁移**：进化成本被摊薄到单问题上（TSP），收益覆盖四个问题——比"逐题进化"的样本效率高一个台阶；
- **保留门槛客观**：新技能必须实测降 gap 才入库，防技能库膨胀污染；
- **配置无关**：同一技能在换模型/换 harness 后仍可用，抗生态变化。

## 局限（如实标注）

- 无官方实现（GitHub search 2026-11-25 实查），复现需自行搭建开发决策记录与回溯归因管线；
- 四个 CO 问题的具体名单、gap 的绝对水平（除 TSP 0.52%/0.98% 外）在摘要截断处之后，本卡未读 PDF；
- "仅在 TSP 上进化"意味着进化信号可能偏向 TSP 特征，第三、四问题的增益幅度存疑（聚合优于基线 ≠ 每题都优）；
- 技能进化依赖外部评估器可跑（CO 有天然 gap 度量），搬到评估信号弱的任务（开放类）不直接适用。

## 如何用于比赛（比赛映射展开）

- **黑客松-数据与算法**（reuse_cost 中）：把 AutoSECO 的循环嵌入竞赛 agent 工具链——每场练习赛/往届题开发完求解器后，跑一次"缺口回溯→技能改写→新解验证"，把技能文档带进正式赛；题目不可预期时，跨题可复用的开发经验就是差异化底牌；开发决策日志（tool-call 级）是实施前提，需在 harness 里先行留痕。
- **ACM-训练体系**（reuse_cost 中）：作为"AI 辅助训练体系"蓝图的过程组件引用——选手（或 AI 助教）把每次题解开发的经验按"缺口归因→通用指令化→复验保留"沉淀成队内技能库；与自动解题承诺解耦，符合 ACM 方向"只出训练体系"的边界。
