# DISCERN：agent 记忆的问题不是"找不找得到"，是"指代谁、以哪个时间态为准、敢不敢答"

> 来源：https://arxiv.org/abs/2611.15729 （v1 2026-11-11，摘要经 arXiv API 实抓）；GitHub search 无官方实现（2026-11-19 实查）。本卡内容出自本次抓取的摘要，未读 PDF 全文。

## 是什么

**DISCERN（DISambiguation and Cross-session Episodic memoRy Navigation）**：单规则架构——**写时保全，读时裁决**。写时构建**严格只增的双时间戳（bi-temporal）溯源图**：永不合并可混淆实体、永不丢弃被替代的旧值。读时用**零 LLM 工具面**驱动 agentic 循环导航该图，终态动作走**四值门控**（答什么/以哪个时间态/证据不足则明确弃权）。配套发现：在 ENT-310（310 查询、100 条不可答）上，普通 RAG 读取器的召回支柱已接近饱和（0.93-0.98）——**真正没解决的是 resolution**（查询指哪个实体、哪个时间态是最新的、要不要弃权）。官方口径：弃偿 F1 0.924（八基线最高 0.802），宏平均正确率 0.861 vs 0.806，领先由实体消歧贡献（0.800，基线无一超过 0.40）；零调参迁移到 LoCoMo 全集同样领先（0.663 vs 0.638）。

## 解决什么问题

企业 agent 跨几十个会话积累的记忆里，事实互相矛盾、被更新、同名实体在嵌入空间糊成一团。学界把这当检索问题，DISCERN 用数据证明不是：检索饱和了，**裁决没解决**。解法是把"写入时怕丢信息"与"读取时做决定"彻底分开——写入层拒绝任何有损合并，裁决层集中处理消歧/时态/弃权。

## 相比前方法优势

- **问题重定义有数据支撑**：0.93-0.98 的召回饱和度+0.40 上限的实体消歧，"recall solved, resolution unsolved"的论断自带证据；
- **只增不并的溯源图**：与主流"写入时合并/总结"的记忆系统反着来——合并造成的歧义在源头被杜绝，旧值保留使时间态裁决成为可能；
- **读时零 LLM 工具面**：导航与裁决靠确定性工具而非生成，成本低且行为可审计；
- **四值门控含弃权**：把"宁可不答"做成一等公民动作，这恰是基线们丢分的地方（0.802 vs 0.924）。

## 局限（如实标注）

- 无官方实现（2026-11-19 GitHub search 实查），双时间戳图+工具面需从零自建；
- ENT-310 为合成基准（作者自建），企业真实数据上的数字需自行校验；LoCoMo 迁移领先幅度小（0.663 vs 0.638）；
- 四 judge LLM-as-a-Judge 评委会本身的偏差未讨论；
- 只增不并意味着存储无界增长，长期运行的压缩策略缺席。

## 如何用于比赛（比赛映射展开）

- **黑客松-数据与算法**（reuse_cost 中）：多轮/多会话数据问答项目照抄其两段式：存储层用"带 valid_from/valid_to 与 chunk 溯源的图/表"替代向量库直接合并；问答层强制四值出口（答案必须带时间态引用，证据不足输出'无法确认'）——评审最容易问的'它说错了怎么办'有结构性回答；ENT-310 的可答/不可答混编思路可自建 30-50 条测试集做演示。
- **双创-文书与申报**（reuse_cost 中）：企业知识助手类项目以"实体消歧 0.40→0.800、拒答 F1 0.924"作为差异化对标数字，架构叙事（写时保全/读时裁决）一句话讲清合规优势。
