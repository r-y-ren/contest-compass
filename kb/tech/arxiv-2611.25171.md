# BGAA：让"过去"当预测的验证器——时序版 test-time compute 的因果化做法

> 来源：https://arxiv.org/abs/2611.25171 （2026-11-18，摘要经 arXiv API 实抓 2026-11-25）。无官方实现（GitHub search 2026-11-25 实查）。本卡内容出自本次抓取的摘要，未读 PDF 全文。

## 是什么

**Backtest-Gated Augmentation Averaging（BGAA）**，面向 TSFM 的测试时计算（TTC）算法。核心洞察：LLM 的 TTC 食谱（生成-验证-选择）不能直接搬到预测，因为**预测器必须因果——不能拿未来信息给候选打分**。BGAA 用序列自己的历史构造验证器：对上下文做**结构化视图变换**（增强），用**滚动起源回测（rolling-origin backtests）**给每个视图打分，**淘汰跑不过"未变换原始上下文"的视图**，把幸存视图的预测分布做平均。摘要口径：每个测试过的 TSFM-benchmark 组合都有改进——GIFT-Eval MASE -0.5~1.0%、fev-bench -1.3~5.0%、第三基准 -1.7~5.9%；小模型场景下 TTC 后的 BGAA 能胜过同族 1B/2.5B 模型。

## 解决什么问题

时序预测模型一次前向出结果，对分布漂移和非平稳性脆弱；LLM 界的"多候选择优"增益对时序不迁移，卡点在**验证**：语言模型可以验证证明、跨样本投票，预测器的候选预测却没有可靠的打分器。BGAA 的回答是：验证器不需要新模型，**历史回测就是免费的因果验证器**。

## 相比前方法优势

- **因果纪律**：与直接套 LLM 式自一致性/多候选投票的做法不同，视图打分只用历史回测，不泄漏未来；
- **门控而非盲平均**：增强视图先过"必须跑赢原始上下文"的淘汰线，防止坏视图稀释预测——比朴素增强平均更稳；
- **诚实增益报告**：53 个 cross-fittable GIFT-Eval 配置上区分了三层量级——已部署策略 +0.4-1.3% CRPS、逐配置 oracle +1.4-4.1%、逐窗口 oracle +17-19%，明说剩余挑战在**窗口级视图选择**（这不是吹爆的论文，是标好天花板的论文）；
- **模型无关**：作用于冻结 TSFM 的推理期，不动权重。

## 局限（如实标注）

- 无官方实现（GitHub search 2026-11-25 实查 0 结果），复现需按摘要自行实现（回测门控逻辑本身简单，但视图集合的具体构造细节在全文里，本卡未读 PDF）；
- 已部署口径的增益量级偏边际（GIFT-Eval CRPS +0.4-1.3%），fev/第三基准的 -1.3~5.9% 更可观但依赖基准；
- 滚动起源回测本身要花推理期算力：视图数 × 回测窗口数的计算开销在长上下文/多序列场景需评估（摘要未报开销数字）；
- "有用的视图有结构化、模型相关的效应（prior-transport 解释）"是摘要级的定性观察，落地时仍需逐模型调视图集。

## 如何用于比赛（比赛映射展开）

- **数模-预测与评估**（reuse_cost 中）：把 BGAA 当"最后一层推理期改进"——骨干（Chronos/TimesFM 或自训模型）出多个增强视图候选，用赛题自身训练段做滚动起源回测筛视图、幸存者平均；因果纪律使其天然通过"没用未来数据"的评审质询；回测淘汰率、视图贡献度都是论文里现成的分析图表素材。
- **Kaggle-竞赛**（reuse_cost 中）：时序赛的标准操作是"冻骨干+堆推理期技巧"，BGAA 与库内修正族正交——MORA（2611.15413）修正已有预测的均值结构，BGAA 在生成端筛选更好的候选分布；两者可串行组成"生成筛选+事后修正"管线。窗口级 oracle 差距 17-19% 提示：若能按窗口特征（如近期波动率）自适应选视图，还有一层可挖。
