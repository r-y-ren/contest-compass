# ArcRAG：检索器与图构建解耦——查询时现场归纳接口

> 来源：https://arxiv.org/abs/2611.06481 （v1 2026-11-04，摘要经 arXiv API 实查；GitHub search 2026-11-13 实查无官方实现）。本卡内容出自本次抓取的摘要，未读 PDF 全文。

## 是什么

GraphRAG 的**跨构建可移植性（cross-construction portability）**研究：一个检索程序换到另一条图构建管线上还能不能用？此前该问题几乎无人测试——各家的检索策略都围绕自家构建产物设计。**ArcRAG** 的方案：推理时从问题命中的实体出发**归纳查询局部图接口**（可达的节点标签、关系描述符、属性键），对着这个局部接口规划多跳遍历，再以 Cypher 执行并自我修复。实验矩阵：MuSiQue、HotpotQA、TriviaQA 三语料各建两种图——schema 引导图（类型化节点/封闭关系集/来源出处）与开放 IE 图（无类型节点/自由文本关系），检索器配置在两者间完全固定；对照构建无关的 Direct-Cypher agent，逐阶段消融（重试/通过预算两轴），并与既往 GraphRAG 系统报告值对比。结论：**检索不必与图构建共同设计**——查询时接口归纳能让构建无关的检索器在构建变更后保持有效，但构建方式仍决定绝对精度上限。

## 解决什么问题

GraphRAG 的隐性锁定：检索策略与图构建管线耦合，换构建=检索层重写+重调。系统评估与工程选型都因此失真——"我的检索好"可能只是"我的图配我的检索"。ArcRAG 把"换个构建还剩多少有效性"变成可测量的量。

## 相比前方法优势

- **首个跨构建系统性测试**：三语料×双构建×固定检索配置的对照矩阵，先前 GraphRAG 工作基本只测自家构建；
- **接口归纳而非 schema 适配**：不读全局 schema、不依赖关系名，现场从问题实体归纳局部接口——构建无关性的来源；
- **Cypher 生成+修复闭环**：遍历计划落成可执行查询，失败可修，工程可用性高于只出检索路径打分的研究；
- **结论可直接指导选型**：构建决定绝对精度、检索器决定跨构建稳定性——两条选择准则分离，选型不再混为一谈。

## 局限（如实标注）

- **无官方代码**：GitHub search 无实现仓，复刻需自建三语料双图构建 + agentic 检索循环，成本不低；
- "与既往系统报告值对比"是跨论文口径，非同环境复跑，横向数字要打折看；
- 摘要未给各阶段贡献的量化拆分（接口归纳 vs 修复 vs 预算的消融数字）；
- 三个 QA 语料都是短文档多跳问答，超长文档/多模态图的接口归纳是否成立未验证。

## 如何用于比赛（比赛映射展开）

- **黑客松-数据与算法**（reuse_cost 中）：GraphRAG 题的检索层架构直接按 ArcRAG 模式搭：实体链接→局部接口归纳→遍历规划→Cypher 执行修复。最大的实战收益是**抗变更**：比赛中途换 LLM 抽取器/改图谱 schema 时检索层不动；Direct-Cypher 对照设置可当 baseline 消融，答辩时能讲清"哪段增益来自哪里"。
- **数模-数据分析与决策**（reuse_cost 高）：多文档互证/溯源分析题把它当证据收集骨架：schema-guided 图的"类型化节点+封闭关系+来源出处"三件套是数据组织规范，检索循环产出带出处的证据链可直接进论文的核查章节。无现成实现，自建成本高，仅在题目确实需要图谱级取证时选它。

**族内定位**：库内 GraphRAG 线已有 PonsRAG（arxiv-2608.25486，长叙事认知岛桥接）、SelfGraphRAG（arxiv-2608.25123，合成 QA 补监督）。ArcRAG 占"**跨构建可移植性/检索-构建解耦**"位——前两者优化"检索质量"，本卡优化"检索器的构建无关性"，正交可叠加。多跳迭代检索的查询演化另有 QueryFlow（本批姊妹卡：图上下文驱动的查询状态演化，优化单构建内检索质量）；同批 EviCast 答"检索值不值得开"的前置决策题。四者组成"要不要检索→检索器怎么搭→跨构建稳不稳"的完整决策链。
