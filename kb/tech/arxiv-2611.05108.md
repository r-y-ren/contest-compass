# Continual AutoResearch：agent 的跨任务经验，留了有用吗？

> 来源：https://arxiv.org/abs/2611.05108 （v1 2026-11-03，摘要经 arXiv API 实抓，2026-11-07）。本卡内容出自本次抓取的摘要，未读 PDF 全文。

## 是什么

autoresearch（agent 自主写代码、跑实验、迭代改进 ML 方案）评测的盲区：多数评测每个新问题都从零开会话，昂贵且无法回答"agent 能否跨任务留存并运用经验"。本文提出 **Continual AutoResearch** 开放环境：同一 agent 的**持久实例 vs 重置实例**在匹配的任务流、数据、时间预算下对控，覆盖 9 个任务族（合成任务、符号回归、**时序预测**、表格 AutoML 等），对 5 个前沿 agent 测量首解质量、研究效率、最终 held-out 性能，并用**记忆消融**（变化 agent 能保留什么）区分"洞见迁移"与"会话连续性"。

## 解决什么问题

"agent 跨任务学习"此前是口号不是测量对象——没有对控就没有归因。本文把问题拆成两个可测命题：持久状态是否提升**效率**（更快更强首解）、是否提升**终局质量**（held-out 最终解），并用消融把增益归因到具体记忆内容。

## 相比前方法优势

- **结论锋利且反直觉**：持久状态对 5 个 agent 的**研究效率全员提升**（更早找到更强解），但这些增益**不一致转化为更好的最终解**——"保留经验"与"有效运用经验"是两种不同能力；
- **实验设计干净**：同 agent 同任务流对控 + 记忆消融三臂，比"加了记忆模块分数涨了"式的单臂演示可信得多；
- **任务族贴数模**：时序预测、表格 AutoML、符号回归在任务族里——结论对数据竞赛自动化管线的可迁移性比通用 coding 基准高；
- **成本视角**：reset 式评测的昂贵性被量化，为"要不要养一个常驻 agent"提供依据。

## 局限（如实标注）

- 摘要未给出效率增益与最终质量差异的具体数字，需读全文；
- 5 个"前沿 agent"的身份/规模未在摘要说明，结论对中小模型的适用性未知；
- 环境与代码释出情况摘要未提及，本轮实抓未见仓库——按 paper 处理；
- 任务流内任务相似度决定迁移空间，"九任务族"内部的亲疏结构未在摘要给出；记忆消融的"保留什么"档位细节需读全文。

## 如何用于比赛（比赛映射展开）

- **数模-数据分析与决策**（reuse_cost 低）：设计自动化解题/调参管线时的分流依据——记忆系统定位为"效率工具"（模板复用、坑位清单、CV 套路），final 方案质量靠当场实验而非历史经验兜底；论文写作时可直接引用其"效率增益普适、终局增益不一致"的对控证据支撑设计取舍。
- **黑客松-数据与算法**（reuse_cost 低）：自动 ML 工程 agent 赛的赛制适配策略——按"计分看进度还是看终局"决定是否投入持久会话工程；其记忆消融协议可改造为自查清单：自己的经验库条目是否真的被下游检索并改变动作。

**族内定位**：库内自进化家族已有 FASE（自进化时序预测 agent，方法卡）、RRSI/Harness Evolution（harness 层自改进）、omp 系（编排插件）——本卡占"**跨任务经验价值的对控评测**"位：不提出新 agent，而是给整个家族提供"经验复用何时兑现"的元证据；FASE 的单任务自进化与本卡的跨任务评测互为内外环。
