# MemoryDojo：投毒不发生在会话里，发生在记忆里

> 来源：https://arxiv.org/abs/2611.09721 （v1 2026-11-06，摘要经 arXiv API 实抓 2026-11-10）。本卡内容出自本次实抓摘要，未读 PDF 全文；GitHub search（2026-11-10）无论文官方实现（IBM/memorydojo 实查为 repo 模板空仓）。

## 是什么

量化"经 agent 记忆系统的投毒"的基准：追踪恶意信息在记忆生命周期（写入→存储→检索→作用于后续会话）中的传播并度量其对 agent 行为的影响。规模与覆盖：**155 条**多会话长程轨迹、四个领域、支持 **五种**记忆系统，可扩展。评测发现：所有被测记忆系统均可被投毒，但下游影响因记忆系统处理/检索方式不同而**差异显著**；进一步提出**记忆感知的毒化优化**流程，能提高投毒效果并凸显记忆架构间的差异。

## 解决什么问题

记忆让 agent 在多会话长程任务上受益，同时引入新攻击面：一个会话中遇到的恶意指令会被存储、随后在别的会话被检索执行。此前缺一个跨记忆架构、按生命周期追踪、可比较量化影响的基准——不同记忆系统"中毒后病得多重"无法横向比较，防御也就无从下手。

## 相比前方法优势

- **跨会话威胁模型**：攻击效果在"投毒会话"与"受害会话"之间隔着记忆系统，比单轮 prompt 注入更隐蔽更持久，基准首次把这一链路做成可测量对象；
- **架构横向可比**：五种记忆系统同一载荷下的差异实测，直接回答"哪种记忆设计更抗毒"；
- **攻防双向可用**：记忆感知毒化优化给出攻方上限（先了解防御要面对什么），各系统的易感差异即是防御侧的检查表。

## 局限（如实标注）

- 未读 PDF 全文：五个记忆系统的具体名单、155 条轨迹的任务构成、毒化优化的算法细节与提升幅度以摘要口径为准；
- 无官方开源实现（GitHub search 2026-11-10），按论文构造多会话轨迹与接入多记忆系统有工程量，reproducibility 定为 medium；
- 基准聚焦"记忆是否被投毒并执行"，对真实系统中的部分可控因素（用户权限、记忆老化）未覆盖。

## 如何用于比赛（比赛映射展开）

- **黑客松-数据与算法**（reuse_cost 中）：agent 安全攻防赛的双向用法——出题方照其结构造跨会话投毒题（轨迹 + 记忆系统 + 传播度量三要素）；参赛防御方按"写入消毒 / 检索过滤 / 跨会话隔离"三道工序自查，"所有系统均易感"的实测结论说明单靠一种手段不够。
- **双创-文书与申报**（reuse_cost 中）：带记忆的 agent 产品（个人助理、企业知识代理）的安全叙事引用：以"投毒跨会话传播 + 架构易感性差异"的具体威胁模型支撑记忆层安全功能（消毒、隔离、审计日志）的必要性论证。
