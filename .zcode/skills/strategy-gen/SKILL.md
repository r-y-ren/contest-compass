# K-02 strategy-gen：战役咨询与方案书（v2 两态一闸门）

## 输入

- `kb/INDEX.md`（唯一入口；需要细节时按索引定位到条目再精读）
- `config/profile.yaml`（未填写则先向用户收集，或声明按"通用学生队低配"假设）
- 用户指定：赛事 ID 或方向描述

## 流程

1. **矩阵评分**：对 INDEX 中候选赛事逐个打分（时间窗匹配 2–10 周最优 / 技术契合度=KB-2 卡片与该赛
   获奖模式重叠——**"大显身手"信号显式化：近 90 天入库新卡 × 该赛 patterns 分布命中，作为加权项** /
   通吃度=同一作品可复投数 / 画像匹配 / 竞争密度）。**每格标注证据强度**（该赛 patterns 有/无、
   KB-2 卡数）——证据不足的维度如实降权并告知"该维度基于有限数据"，禁止假装有依据
2. **grilling 前置步**：以 `kb/INDEX.md` 与相关条目为语境，对用户做**完整 grilling**（决策树多轮
   问答，frontier 问空为止、用户喊停即止）——至少澄清：选赛意图与优先级 / 时间窗与人力约束 /
   作品范围边界 / 技术栈偏好与风险容忍 / 一鱼多吃期望
3. **咨询态（默认，零落盘）**：对比矩阵 + 一鱼多吃路线 + 三节方案概要（赛事/方案/技术栈）——
   **只在对话里回复，不生成任何文件**（含 grill 纪要）
4. **硬闸门：显式询问"是否开始战役？"**——不可跳过、不可默认、不可替用户决定：
   - **否** → 结束（产物说明：无产物，对话交付）
   - **是** → 建档（新战役收口：`init_state --campaign <cid> --phase deliver` 登记 +
     `repo_split bootstrap --path workspace/<cid> --push` 建项目库入清单）；已有战役上下文
     （`--campaign` 显式 / 恰一登记战役自动选中 / 多战役必填）时跳过建档
5. **落盘态**：按 `config/templates/brief-template.md` 产**三节方案书**（赛事：情报摘要回链+
   对比矩阵+大显身手信号；方案：主张+一鱼多吃+范围边界+推荐结论；技术栈：kb_tech_ids+合规
   mode 判定）+ grill 纪要 → `<战役根>/docs/briefs/<日期>-<赛事slug>-<方案slug>.md`（与同
   slug `-grill-notes.md`），自动建目录；随后**项目仓库 commit + 立即 push**（铁律 6，随项目版本管理）
6. **收尾**：`python scripts/maint/doc_lint.py --project <战役根>` 跑禁用节护栏（R5）；
   产物说明列出落盘清单与护栏结果

## 纪律

推荐结论必须引用具体 KB 条目 ID 并携带抓取日期（铁律 1），禁止凭印象；ACM 方向只出训练体系类
参考方案；方案书是**纯参考信息**——不得充当推进契约、不得影响后续推进；**禁止**含 milestones/
acceptance/接口契约/需求种子等推进指令。**单源不双写**：落盘副本只有战役侧一份，咨询态零副本。
摘引外部原文时原文仍归 `<战役根>/references/` 并登记 INDEX（铁律 3）。
